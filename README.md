# evidence-to-action · 查证、推进与汇报

一个可独立使用的 Codex skill：把多步骤任务推进到有据可查、顺序合理、可执行、可验收的结果，并写成清楚连贯的报告。

## 解决什么问题

- 数据有出处，但关键结论无法追溯到原始记录。
- 步骤列得完整，却没处理前后依赖和交接。
- 已安排、已提交、已生成与已完成混用。
- 报告堆数字、讲道理，却没有具体判断和下一步动作。

核心工作链：明确目标 → 核实事实和口径 → 形成有边界的判断 → 按依赖安排工作 → 执行与验收 → 汇报与交接。

## 安装

将整个仓库目录放入 Codex 的个人 skills 目录，目录名保留为 `evidence-to-action`，确保 `evidence-to-action/SKILL.md` 存在。若自定义了技能目录，使用相应位置。

支持自动选择，也可以明确调用：

```text
请使用 $evidence-to-action 完成这项工作：先查清依据和数据口径，
按依赖安排顺序，执行并验证，最后给出简明、可追溯的报告。
```

新增技能可能需要新聊天或刷新技能列表后才能被发现。自动选择不保证每次触发。

## 使用示例

```text
使用 $evidence-to-action，把这些材料整理成项目进展报告。
区分已完成、待验收和计划事项，指出口径冲突并附来源定位。
```

```text
使用 $evidence-to-action，调查这个流程为什么反复卡住。
还原一个典型案例，识别输入、决策、交接与验证的具体问题，
完成当前授权范围内的改进，并给出接续清单。
```

## 独立性与范围

不依赖其他 skill、专用数据库、API 密钥或额外服务；使用当前环境已有工具。简单问答和小修改直接完成，不强制建立复杂流程。

技能包仅包含通用方法和虚构示例，不包含私人文件、个人标识、本机路径、聊天记录或凭证。

## 验证

可使用 Codex `skill-creator` 提供的 `quick_validate.py` 检查技能格式，并检查引用文件是否存在。进一步用口径冲突、未验收事项及小任务场景检查行为。格式校验不代表长期任务效果已经得到验证。
